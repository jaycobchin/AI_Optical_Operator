# Repository instructions

## Changelog maintenance

- Update `CHANGELOG.md` as part of every meaningful change to application behavior, fixes, dependencies, setup, configuration or documentation. Do this before declaring the work complete and include the entry with the corresponding changes when committing.
- Add concise entries under `Unreleased`, grouped by the type of change. Explain the resulting behavior and include migration or setup steps when relevant.
- Record only checks actually performed. Distinguish completed implementation from planned work, and keep known limitations accurate.
- Preserve historical version sections. Move relevant unreleased entries into a dated version section when preparing a release; do not invent release dates or bump versions for routine documentation edits.
- Keep the README's changelog link and any affected setup instructions current. A changelog entry does not require rewriting the supplied specification or archived documents.
- This is an instruction for agents working in this repository. It is not a background changelog generator; contributors editing outside this workflow must maintain the changelog themselves.
